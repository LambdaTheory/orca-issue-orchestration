# [用户决定] <需要用户拍板的问题>

> 用法：复制本文件为 Issue 正文；替换 `<...>`。
> 标题：`#<n> [类型] <主题>`；`<n>` 用建票后的真实编号回填。
> 本票是**用户决定节点**，不产出代码。
> 固定标签：依赖未满足时**不打** `needs-user`；成为当前前沿后加 `needs-user`，仍阻塞下游/交付时再加 `gate`；关闭时移除两者。
> 任务标签：`<task-name>`（简洁英文小写 kebab-case）（建票即加，本任务所有票统一，关闭不摘除）。
> 成为前沿后 assign 给已核实用户账号，并发一条以「需要你处理」开头的评论，写清选项与回复方式。

## 目标

用户节点：需要你决定 <问题>，以便 <解锁什么工作 / 避免什么不可逆后果>。
本票不产出实现。

## 确认依据

- 背景与原话：<用户提出的约束、需求或此前决定>
- 已核实事实：<会影响选项的事实，附来源>
- 相关票 / PR：<#n；当前状态>

## 待决定事项

**问题**：<一句话说清要选什么。>

| 选项 | 内容 | 影响 | 代价 / 风险 |
|---|---|---|---|
| A（推荐） | <做法> | <结果> | <代价> |
| B | <做法> | <结果> | <代价> |
| C | <不做/延后> | <结果> | <代价> |

**推荐**：<A，理由。>
**不可逆 / 对外影响**：<是否有；没有写“无”。>

## 需要你做什么

1. 阅读上面的选项与影响。
2. 以**新评论**回复：选项字母 + 必要补充（例如授权范围、目标分支、数据范围）。
3. 若选择授权类动作（合并、改真实数据、扩大权限），请写明授权对象与范围；未写明的部分不视为授权。

<示例回复：`A，授权合并 PR #16，仅限该 PR，不含后续改动。`>

## 范围

- 要做：由你作出决定并写明范围。
- 不做：本票不实现功能、不代替你决策；决定本身不等于对未说明动作的授权。

## 验收

- [ ] 你的决定已记录在本 Issue 的新评论中。
- [ ] 决定包含必要范围（对象、分支、数据、权限）。
- [ ] 若决定授权外部动作，协调者执行并核实结果后写入本票。
- [ ] 仍有未决子问题时，本票保持开放，不提前解锁下游。

Blocked by: <无；或真实 #n>

## 交付

无代码交付。决定取得并记录后，由协调者写结论与依据并关闭本票。
若决定授权了具体动作（如合并 PR），需核实该动作实际完成后再关闭；执行失败或结果未知时保留开放并记录阻断。

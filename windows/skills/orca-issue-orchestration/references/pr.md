# PR 规范

开发 worker 按任务说明创建或更新 PR 时执行本节；协调者交付复核使用同一标准；独立评审只读，不修改分支或正文。

> 平台：本文件命令示例按 bash / zsh 书写，Windows 需换成 PowerShell 等价执行——保存 PR 正文用单引号 here-string `@' … '@`（见下文），读取文件内容用 `Get-Content -Raw -Encoding UTF8`；git log/diff 等命令两端同形可直用。

本规范只约束 PR 的标题、正文、Issue 关联和证据呈现。分支隔离、worktree、依赖顺序、派发授权、评审与合并属于编排主线和项目配置，不在这里重复；PR 交付后是否合并、何时关票也按项目配置执行。

## 参数来源

| 参数 | 来源与默认 |
|---|---|
| 目标分支 | 任务说明与项目编排配置的 `<目标分支>`；不默认 `main` |
| 标题格式 | 项目约定；未约定时用 `<type>(<scope>): <摘要>`，无 scope 时用 `<type>: <摘要>` |
| 发布标记 | 仅当项目明确要求标题后缀（如 `[dev]`）时使用；未要求则不加 |
| 正文语言 | 默认中文；项目明确要求其他语言时从其约定 |
| 影响面章节 | SQL、前端/客户端、脚本与配置三节按项目配置保留；未声明时写固定“不涉及”文案 |
| Issue 关联 | 合并即满足该票全部完成条件才写 `Closes #n`，否则写 `Refs #n` |

## 标题

- 格式：`<type>(<scope>): <简明摘要>`；不写来源分支名，来源分支放在正文。
- 只写一个变更主题，不堆票号、不写 WIP、不把多个不相关改动塞进同一标题。
- 项目要求发布标记时，末尾恰好保留一个；不得出现 `[dev][dev]` 或错误标记。
- 标题不用于证明目标分支；base 以 PR 实测值为准。

示例：

```text
feat(api): 增加订单重复提交校验
fix(ui): 修复确认页重复拉起签约[dev]
```

## 正文

正文必须来自该 PR 分支相对目标分支的真实提交与 diff，不凭记忆、分支名或本地未提交文件推断：

```bash
git log --reverse --format="%h %s" <REMOTE>/<目标分支>..<REMOTE>/<BRANCH>
git diff --name-status <REMOTE>/<目标分支>...<REMOTE>/<BRANCH>
git diff <REMOTE>/<目标分支>...<REMOTE>/<BRANCH>
```

章节顺序固定，空章节写固定文案，不省略标题。

### `## PR 概述`

说明本 PR 将 `<BRANCH>` 合入 `<目标分支>`，并概括 reviewer 需要关注的主题。

### `## 本次变更内容`

按后端、前端、部署、配置、测试、文档等实际涉及的部分分组；写出重要文件或模块及行为影响；排除本地未提交和未跟踪文件。

### `## 关联 Issue`

列出关联票号并说明 `Refs` / `Closes` 的选择理由。仍需验收、其他 PR 或用户决定时用 `Refs`；只有合并即满足该票全部完成条件时才用 `Closes`。

### `## 关联 Commit SHA`

列出 PR 范围内的全部 commit，包含存在的 merge commit；使用至少 8 位短 SHA 和准确的 commit headline。

### `## SQL / 数据库影响`

检查真实 diff 中的 `.sql`、迁移目录（如 `db/migration/`、`V*.sql`）、DDL、DML、schema 与数据脚本。没有时固定写：

```text
本 PR 不包含 SQL 文件变更，未发现新增 DDL / DML 或迁移脚本。
```

有时逐个列出文件，并说明运维影响、受影响表和可回滚性；无法从 diff 判断时停止并向协调者提问。

### `## 前端 / 客户端发布影响`

本节始终保留。项目没有前端或客户端时，固定写“本 PR 不涉及前端代码变更，无需发版”；有发版要求时按项目配置写明结论。

- 基于真实 changed files 判断，不凭分支名或记忆。
- 涉及前端时列出具体文件或模块，并写明“需要发版后才能验证”或“不涉及发版”。
- 无法判断时停止，确认前不创建或更新 PR。

### `## 关联脚本与配置文件`

检查真实 diff 中的 `.sh`、`.ps1`、`.py`、CI 配置、`deploy/` 下脚本、Compose 文件、`.env.example*`、`application-*.yml` 等。没有时固定写：

```text
本 PR 不涉及脚本或配置文件变更。
```

### `## 测试与验证说明`

列出新增或修改的测试；写明验证命令、结果、执行环境、适用范围、对应 SHA 和证据位置。标出合并前需要关注的检查项，例如环境变量、迁移顺序、服务重启或 CI 证据。

- 未执行的测试不得写成通过。
- 同 SHA 且环境与范围未变的有效结果可以复用，引用原证据位置。
- 有新改动、新失败或未解决疑点时，只补本次范围与回归点，不默认全量测试或 build。

### 正文写入

先写到临时文件再传 `--body-file`，避免多行文本在 shell 中被改写：

```bash
body_file=$(mktemp)
cat > "$body_file" <<'EOF'
## PR 概述

本 PR 将分支 <BRANCH> 合入 <目标分支>。

## 本次变更内容

- 用真实 diff 内容替换本行。

## 关联 Issue

Refs #<n>

## 关联 Commit SHA

- abcdef12 - feat(scope): headline

## SQL / 数据库影响

本 PR 不包含 SQL 文件变更，未发现新增 DDL / DML 或迁移脚本。

## 前端 / 客户端发布影响

本 PR 不涉及前端代码变更，无需发版。

## 关联脚本与配置文件

本 PR 不涉及脚本或配置文件变更。

## 测试与验证说明

- 命令：<命令>
- 结果：<结果>
- 环境与 SHA：<环境> / <SHA>
- 证据位置：<PR 评论或文件路径>
EOF
gh pr create --base <目标分支> --head <BRANCH> --title "$title" --body-file "$body_file"
gh pr edit <PR_NUMBER> --title "$title" --body-file "$body_file"
```

Windows PowerShell 用单引号 here-string（`@' ... '@`）保存正文；仍优先使用 `--body-file`。

工作 worker 创建 PR 时不写工作时长，也不留占位；该章节由协调者在 `S finish` 后回填。

## 工作时长（收口回填）

总历时只在 `S finish` 之后才有最终值。协调者负责回填，worker 不估算、不手写、不提前写。

- **回填对象**：本次 Run 关联 PR 中 `mergedAt` 最晚的一个；没有已合并 PR 时取最后交付的 PR；没有任何 PR 时不回填，保留 `.orchestration/<run>/timing.md` 并在最终报告说明。用 `gh pr view <n> --json number,state,mergedAt` 核对，不按 PR 编号大小猜。已合并 PR 也允许编辑正文，这不改变合并结果。
- **命令**：`PT --pr <PR>`。脚本读取 `state.json` 生成固定章节，保留正文其他部分；已存在 `## 工作时长` 时原地替换，不重复追加。
- **回读**：编辑后用 `gh pr view <PR> --json body,url` 核对恰好一个 `## 工作时长`，数值与同时刻的 `S timing` 一致。更新失败保留 `timing.md` 并报告，不宣称已回填。
- **格式**：

```text
## 工作时长

- 总历时：6h42m（2026-10-20 09:00 → 15:42）
- 有效工作：3h05m（开发 1h50m · 评审 40m · 修复 20m · 验证 15m）
- 等待：3h37m（待派发 10m · 阻塞 25m · 等用户 3h02m）
- 结束状态：完成
- 统计口径：从 skill 启动（C start）到收口（S finish）的墙钟时间；并发任务按 Issue 累加，明细见 `.orchestration/<run>/timing.md`
```

- 暂停或取消回填实际墙钟，结束状态写“暂停”或“取消”，不写成完成。
- 不手工改数字；口径或阶段有疑问时回到 `S timing` 和 `timing.md`。

## 创建与更新

- 新建 PR 显式传 `--base <目标分支>`，不依赖仓库默认分支。
- 任务说明要求继续同一 PR 时才执行 `gh pr edit`；先回读现有 base/head，确认同一任务后再改。
- 发现该分支已有属于其他任务的 PR 时停止，向协调者报告；不接管、不改 base、不把两个任务合并到一个 PR。
- 只追加提交；不改写已推送历史、不 force-push。评审基点和待审 SHA 依赖稳定历史。
- 不在 PR 中合并、不关闭 Issue、不代替协调者做交付结论。

## 写入后回读

创建或编辑成功后立即回读，不以命令输出或参数作为成功依据：

```bash
gh pr view <PR_NUMBER> --json baseRefName,headRefName,title,url,body
git log --oneline <REMOTE>/<目标分支>..<REMOTE>/<BRANCH>
git diff --name-status <REMOTE>/<目标分支>...<REMOTE>/<BRANCH>
```

- 核对 base、head、标题、正文与任务说明和实际 diff 一致。
- base/head 与任务说明不符：停止，报告期望值与实测值，不凭命令参数或标题宣称目标正确。
- 正文与实际 diff 不符：先修正正文；范围本身不符时停止并报告，不通过扩大描述掩盖。
- 只有回读通过才允许宣称创建/更新成功：

```text
PR: <url>
base: <baseRefName>   head: <headRefName>
```

## 失败处理

| 情况 | 处理 |
|---|---|
| 工作区不干净 | 先提交本任务改动；不把未提交文件写进 PR，不自行丢弃或 stash 他人改动 |
| 来源分支未推送 | 按任务说明推送；失败时报告错误，不换分支绕过 |
| 缺少远端或认证失败 | 展示 `git remote -v` 与错误类别，区别未登录、权限不足、App 未安装；不在聊天中索要令牌 |
| 目标分支不存在或与任务说明不符 | 停止并报告，不自行改 base |
| push 被拒（non-fast-forward） | 停止，报告本地与远端差异；不 force-push、不改写历史 |
| 保护分支或权限错误 | 停止；不启用绕过变量，不改仓库保护设置 |
| 同分支已有 PR | 回读归属；同一任务按“创建与更新”处理，其他任务停止并报告 |
| 创建/编辑后回读不符 | 报告实际值；需要改 base 或标题时由协调者确认后再动，不反复试写 |

## 验收标准

- 标题符合项目格式；要求发布标记时恰好一个。
- 正文基于真实提交与三点 diff，章节齐全，空章节使用固定文案。
- Issue 关联按合并是否满足全部完成条件选择 `Refs` / `Closes`。
- 测试证据包含命令、结果、环境、范围和对应 SHA；未执行的不写成通过。
- 本地未提交、未跟踪文件没有进入 PR。
- 创建或更新后回读过 base/head/title/正文，最终输出包含实测值。
- 没有合并、关票、force-push 或绕过保护分支。
- 收口后的最终 PR 恰好包含一个 `## 工作时长`，数值来自 `S finish` 的 `timing.md`，不是手写估算。
